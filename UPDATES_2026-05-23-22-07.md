# Astrometric Scale Engine: Development Changelog
**Date:** 2026-05-23
**Session:** 3D Astrometric Map & UI Overhaul

## Overview
This session focused on transforming the 3D Astrometric Map into a high-fidelity, interactive, and scientifically accurate visualization engine. Based on the `SYSTEM_REQUIREMENTS-3.md` directives and subsequent iterative feedback, we significantly expanded the data pipelines, enhanced the rendering logic, and polished the navigation UX.

---

## 1. Data Pipeline & Scientific Accuracy

* **NASA JPL Horizons API Integration:**
  * **What we did:** Replaced static or procedural orbital calculations for the solar system with real ephemeris data.
  * **Technical Details:** Overhauled `build_data.py` to query the JPL Horizons system for continuous 3D coordinate vectors. The script now pulls highly accurate, multi-point trajectories for the 8 major planets and the Moon, saving them as an `orbit_path` array within `systemic.json`.
* **NASA Exoplanet Archive TAP API Ingestion:**
  * **What we did:** Massively expanded the deep-space simulation from just 2 exoplanets to over 1,500.
  * **Technical Details:** Automated an SQL-based data ingestion pipeline querying the NASA Exoplanet Archive via `astroquery`. The system filters for all confirmed exoplanets within 100 parsecs, formats their RA/Dec/Distance into cartesian coordinates, and injects them alongside the HYG database stars in `stars.json`.

## 2. Visual Rendering & Aesthetics

* **Authentic Planetary Geometries ("Real Self" Rendering):**
  * **What we did:** Stripped away the massive, generic pink/cyan spherical indicators that previously marked Origin and Destination nodes. 
  * **Technical Details:** Removed the solid `Sphere` geometries from the `<TrajectoryVectors>` component. Major bodies now render authentically with curated color palettes.
* **Planetary Features & Colors:**
  * **What we did:** Differentiated local system objects to match their real-world appearance.
  * **Technical Details:** Adjusted material colors in `SceneGraph.tsx` (e.g. Sol = `#ffcc00`, Mars = `#c1440e`). Implemented a double-sided, semi-transparent `<ringGeometry>` for Saturn. Added a distinct, thin, bright-white ring to Uranus, pitched at ~90 degrees to reflect its extreme axial tilt.
* **Reactive Orbital Highlighting:**
  * **What we did:** Added orbital rings that dynamically respond to user selection.
  * **Technical Details:** Hooked the `<OrbitLines>` component into the global flight state (`useFlightStore`). Orbits belonging to the currently selected Origin and Destination instantly increase in thickness (`lineWidth: 1.5`) and opacity (`0.8`), while unselected orbits remain dim.
* **Trajectory Endpoints & CSS Labels:**
  * **What we did:** Ensured flight paths have clear, distinct endpoints that don't crowd the screen, with labels that never detach or fly off into the void.
  * **Technical Details:** Added scaled cyan/magenta `Sphere` end-caps to the `<TrajectoryVectors>` line. Replaced 3D world-space positioning for `<Html>` labels with CSS pixel offsets (`transform: translateY(-24px)`). This prevents labels from floating lightyears away from their targets when zooming out.

## 3. Navigation & UX Engineering

* **Dynamic Distance Formatting:**
  * **What we did:** Re-wrote the telemetry HUD to intelligently scale distance units based on the scope of the flight.
  * **Technical Details:** Modified the `formatDistance` function in `TelemetryHUD.tsx`. Distances now automatically shift through units: `< 0.01 AU` (km), `< 0.1 ly` (AU), `< 100 pc` (ly), and `> 100 pc` (pc). Added a `LIGHTYEAR_TO_METERS` constant to the physics store.
* **Camera Pivot & Rotation Anchoring:**
  * **What we did:** Fixed disorienting rotation where spinning the camera swung the scene wildly off-screen.
  * **Technical Details:** Rewrote the `CameraController` in `SceneGraph.tsx`. `OrbitControls.target` is now explicitly anchored to the **Origin** node rather than the empty midpoint of the flight path.
* **Strict Double-Click Object Selection:**
  * **What we did:** Solved a critical bug where left-clicking to drag/rotate the camera accidentally snapped focus to background stars.
  * **Technical Details:** Upgraded the `PointCloud` event listener from `onPointerDown` (which triggers instantly on mouse-press) to a strict `onDoubleClick`. This perfectly isolated camera manipulation from object targeting.
* **Camera Recovery & Reset Mechanics:**
  * **What we did:** Gave the user emergency methods to recover the camera if it gets lost in deep space.
  * **Technical Details:** Bound the `Esc` key to a global `handleReset` state trigger. Also bound `onPointerMissed` to the `Canvas` background. Both methods instantly clear the `focusedNode` and snap the camera back to the default Origin/Destination framing.
* **UI Layout Restoration:**
  * **What we did:** Restored the map's full-screen 3D viewport after it shrank.
  * **Technical Details:** Migrated the "Navigation Controls" instructions out of a floating overlay inside `SceneGraph.tsx` and cleanly integrated them as a dedicated section at the bottom of the right-hand `TelemetryHUD.tsx` panel.

## 4. Multi-Scale Mathematics

* **Interstellar Deep Space Clipping & Scaling:**
  * **What we did:** Fixed massive graphical glitches ("giant yellow ring") that occurred when switching to the Interstellar regime.
  * **Technical Details:** The WebGL `Canvas` was modified with an extreme `near: 0.0001` clipping plane to prevent geometry culling at interstellar scales. Additionally, the `<MajorBodies>` (planets/sun) component was strictly disabled when outside the `Systemic` regime. This prevents fixed-radius planetary meshes from mathematically exceeding the distance to nearby stars, allowing Sol to render organically as a standard point within the `<PointCloud>`.
